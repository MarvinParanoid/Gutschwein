# Pinned versions for the runtime dependencies of pyproject.toml.
#
# Deploying means building the image, and `pip install .` on `>=` constraints
# resolves afresh every time — so the same commit could produce a different image
# tomorrow than it did today. The frontend has had package-lock.json all along;
# this is the backend's half, and the reason is on record: docs/deploy.md notes a
# dependency problem that once put production into a crash loop.
#
# A constraints file rather than a requirements file, deliberately. pip still
# resolves for the interpreter it is running on, so a dependency that only exists
# on some Python versions is still picked up; these lines only decide *which*
# version anything named here may be. That matters because this file is generated
# on the developer's Python and installed on the image's.
#
# Regenerate with `make lock` after changing pyproject.toml, and read the diff.
