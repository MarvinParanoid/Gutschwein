# 🐷 Sparschwein

Семейный менеджер купонов (Gutscheine): список, комментарии, история изменений, архив.
Купон добавляется по скрину или фото, поля заполняются вручную. Живёт как Telegram Mini App.

## Основной сценарий

Гутшайн на сумму — это карта с остатком, которую тратят за несколько походов:

1. открыли приложение, нашли карточку нужного магазина (список или поиск);
2. нажали на фото — оно раскрывается **на весь экран на белом фоне**, кассир считывает сканером;
3. нажали «Обновить остаток» — ввели либо сумму покупки, либо остаток с чека.

Остаток обнулился — купон сам уходит в «Использованные». Каждое списание попадает в
историю купона: кто, сколько, когда и что купил.

## Что умеет

- **Список** по вкладкам: активные (сортировка по близости срока), черновики, использованные, архив.
  На карточке — остаток крупно и номинал мелким шрифтом, если карта потрачена частично
- **Остаток** с прогресс-баром, вводом «потратил» / «осталось» и журналом списаний.
  Исправление ошибки — просто ещё одно обновление остатка, обе записи остаются в истории
- **Режим сканирования**: белый фон, картинка на всю ширину, кнопка поворота, код текстом
- **Добавление** — фото боту (создаётся черновик с картинкой) или кнопка «+» в приложении
- **Купон**: магазин, название, код с кнопкой «копировать», номинал/процент, срок, условия, заметка, фото
- **Комментарии** — общие для всей семьи, удалять можно только свои
- **История** — кто и что сделал с купоном (создал, изменил какие поля, списал сумму, заархивировал)
- **Статусы**: черновик → активный → использован; в архив и обратно; удаление насовсем
- **Уведомления в семейный чат**: новый купон, списание с остатком, новый комментарий,
  и напоминание за 3 дня до истечения срока

## Стек

| Слой | Что |
|---|---|
| API | FastAPI, SQLAlchemy 2 (async), SQLite, Alembic |
| Бот | aiogram 3, long polling, в том же процессе |
| Фронт | React + TypeScript + Vite, отдаётся статикой из FastAPI |
| Auth | Telegram `initData` (HMAC-подпись) + whitelist Telegram ID |
| Деплой | Docker, один контейнер, том `./data` |

## Структура

```
backend/
  app/
    main.py        точка входа: lifespan (миграции + бот), CORS, роутеры, раздача SPA
    config.py      настройки из окружения / .env
    models.py      User, Voucher, Comment, Event
    schemas.py     pydantic-модели API
    auth.py        валидация initData, whitelist, upsert пользователя
    services.py    общие хелперы (поиск купона, запись событий, подписи)
    storage.py     сохранение картинок на диск
    notify.py      уведомления в семейный чат
    bot.py         хендлеры бота + цикл напоминаний
    routers/       vouchers, uploads, images, users
  alembic/         миграции
  tests/           тесты API
frontend/
  src/
    api.ts         типизированный клиент + заголовок авторизации
    telegram.ts    обёртка над window.Telegram.WebApp
    format.ts      форматирование дат, сроков, подписей событий
    pages/         ListPage, VoucherPage, VoucherForm
```

## Локальная разработка

```bash
make install          # venv + npm install
make dev-api          # FastAPI :8000, DEV_MODE=true, бот выключен
make dev-web          # Vite :5173, проксирует /api на :8000
```

Вне Telegram `initData` нет, поэтому в dev-режиме фронт отправляет заголовок
`X-Dev-User: 1000`, а бэкенд принимает его только при `DEV_MODE=true`.
**В продакшене `DEV_MODE` должен быть `false`** — иначе доступ открыт любому.

```bash
make test             # pytest
make lint             # ruff + tsc
make migration m="…"  # alembic revision --autogenerate
```

## Развёртывание на VPS

Нужны: домен (A-запись на IP сервера), Docker с плагином compose и открытые порты 80/443.
Telegram открывает Mini App только по **https с валидным сертификатом** — самоподписанный
и голый IP не подойдут.

### 1. Бот и Mini App в @BotFather

```
/newbot                → имя, username, получаете BOT_TOKEN
/setmenubutton         → выбрать бота, ввести https://sparschwein.example.com,
                         подписать кнопку («Купоны»)
```

Отдельная Mini App (`/newapp`) не нужна — кнопка меню открывает то же приложение.

### 2. Код и конфиг

```bash
git clone <repo> /opt/sparschwein && cd /opt/sparschwein
cp .env.example .env && nano .env
```

Заполнить: `BOT_TOKEN`, `WEBAPP_URL=https://sparschwein.example.com`,
`ALLOWED_TELEGRAM_IDS`, `FAMILY_CHAT_ID`, `DEV_MODE=false`.

Оба id узнаются одной командой: напишите боту `/id` в личке (вернёт ваш Telegram ID) и
в семейной группе, добавив туда бота (вернёт id чата — отрицательное число). Команда
работает даже у тех, кого ещё нет в whitelist, так что домашним не нужен доступ к серверу.

### 3. Права на том с данными

Контейнер работает под uid 10001, а `./data` создаётся docker'ом от root — без этого шага
приложение не сможет писать в БД:

```bash
mkdir -p data && sudo chown -R 10001:10001 data
```

### 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f            # «running database migrations», затем «telegram bot started»
curl -s localhost:8000/healthz    # {"status":"ok"}
```

Миграции применяются сами при старте. Контейнер слушает только `127.0.0.1:8000` —
наружу его выставляет реверс-прокси.

### 5. Реверс-прокси и TLS

Caddy получает и обновляет сертификат сам, поэтому это самый короткий путь.
`/etc/caddy/Caddyfile`:

```
sparschwein.example.com {
    reverse_proxy 127.0.0.1:8000
    # Caddy по умолчанию размер тела не ограничивает; ставим чуть выше лимита
    # приложения (12 МБ на картинку), чтобы отсекать мусор раньше.
    request_body {
        max_size 15MB
    }
}
```

```bash
sudo systemctl reload caddy
```

Для nginx понадобится certbot и `client_max_body_size 15m;` плюс проксирование
`proxy_set_header X-Forwarded-Proto $scheme;`.

### 6. Проверка

Откройте бота → кнопка меню → приложение. Пришлите боту фото купона — должен появиться
черновик. Если приложение отвечает «Нет доступа» — в сообщении будет ваш Telegram ID,
допишите его в `ALLOWED_TELEGRAM_IDS` и `docker compose up -d`.

### Обновление и бэкап

```bash
git pull && docker compose up -d --build      # данные в томе, переживают пересборку
tar czf sparschwein-$(date +%F).tar.gz data/  # БД + картинки, больше состояния нигде нет
```

Бэкап стоит положить в cron: `sqlite` держит всё в `data/sparschwein.db`, картинки — в
`data/uploads/`.

## Модель доступа

Одна общая семья: любой Telegram ID из `ALLOWED_TELEGRAM_IDS` видит и правит все купоны.
Разделения на группы нет — это осознанное решение, чтобы не тащить права доступа в MVP.

Картинки отдаются по «capability URL» — `/api/images/<yyyy-mm>/<32 hex>.jpg` без авторизации,
потому что `<img src>` не умеет отправлять заголовки. Имя файла — 128 бит случайности, угадать
нельзя, листинга нет. Побочный плюс: ссылку на скрин купона можно просто переслать в чат.
Если это когда-нибудь станет неприемлемо — отдавать картинки через `fetch` + blob URL.
